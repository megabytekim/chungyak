청약 데이터 인프라 만드는 법

매일 아침 청약 공고를 공공 API로 모으고, 내 조건으로 접수 자격을 가린 뒤 알림·노트·공개 페이지로 내보내는 시스템입니다. 어떻게 생겼고, 어디서 넘어졌고, 직접 만들려면 무엇부터 하면 되는지 정리했습니다.

이게 뭘 해주나

청약홈에는 매일 새 공고가 올라옵니다. 하나하나 열어 보고 "내가 1순위인가", "주변 시세보다 싼가"를 따지는 건 손이 많이 갑니다. 이 시스템은 그 반복 작업을 대신합니다.

  • 모은다. 매일 한 번 공공 API(프로그램이 데이터를 받아 가는 공식 창구)에서 분양 공고, 주택형·분양가, 경쟁률, 무순위(줍줍) 공고, 아파트 실거래가를 받아 DB(데이터를 쌓아 두는 파일 하나)에 쌓습니다.
  • 가린다. 미리 적어 둔 내 조건(통장 가입기간, 예치금, 세대주 여부, 거주지)으로 공고마다 접수 순위를 판정합니다.
  • 잰다. 분양가를 같은 구·비슷한 면적의 최근 실거래와 비교해 "안전마진"을 숫자로 냅니다.
  • 알린다. 텔레그램 알림은 네 가지뿐입니다. 1순위 접수 3일 전, 새 1순위 공고, 관심 지역 무순위의 접수일과 새 공고. 알림마다 그 공고 주택형들의 안전마진 범위가 한 구절로 붙습니다(예: "안전마진 +18%~+31% (동 기준)"). 나머지는 "지금 볼 공고"를 한 장으로 요약한 노트(이하 레이더 노트)를 매일 조용히 덮어씁니다. 공개용 웹 페이지 두 장은 따로 손으로 발행합니다.

당첨을 예측하지 않습니다. 이 시스템이 가리는 것은 "접수할 수 있는 순위"입니다. 가점, 특별공급, 당첨 가능성은 계산하지 않습니다.

개발자용 — 구성 요소
  • DB는 SQLite입니다. 수집기(collectors/)와 판정 로직(core/)은 순수 파이썬입니다.
  • 외부 의존성은 PyYAML과 pytest 두 개입니다. HTTP는 urllib, XML은 xml.etree, CSV는 csv, DB는 sqlite3 표준 라이브러리로 처리합니다.
  • DB 파일은 코드 저장소 밖에 둡니다. 모든 소스가 과거분을 다시 받을 수 있어서 DB는 캐시에 가깝고, 저장소에 바이너리를 넣을 이유가 없습니다.
  • 테이블 10개: notice, notice_unit, rate, trade, unsold, hug_price, match, collector_run, remainder_notice, remainder_unit. 미분양(unsold)은 인증키가 아직 없어 테이블만 있습니다.

쓰는 데이터와 받는 법

재료는 전부 공공데이터포털(data.go.kr)에서 무료로 받습니다. 회원가입 후 "활용신청"을 누르면 인증키(내 계정에 발급되는 접속용 비밀 문자열)가 나옵니다. 키 하나로 여러 API를 부를 수 있습니다. 아래 표의 JSON·XML·CSV는 데이터 파일 모양의 이름이니 몰라도 됩니다.

활용신청 순서

  1. data.go.kr 가입. 무료입니다.
  2. 세 API에 활용신청. 청약홈 분양정보 조회 서비스(데이터셋 15098547), 청약홈 청약접수 경쟁률 및 특별공급 신청현황(15098905), 국토교통부 아파트 매매 실거래가 자료(15126469). 개발계정은 자동승인으로 기록돼 있고, 대개 즉시~2시간 안에 승인됩니다.
  3. 승인 전 호출 주의. 승인이 덜 됐을 때 부르면 HTTP 401/500과 SERVICE_KEY_IS_NOT_REGISTERED_ERROR가 옵니다. 고장이 아니니 1~2시간 뒤 다시 해 봅니다.
  4. HUG 분양가는 신청이 필요 없습니다. API가 아니라 CSV 파일데이터(15061057)이고 인증키도 필요 없습니다.
  5. 미분양은 별도. 한국부동산원 R-ONE에서 따로 키를 받아야 합니다. 이 시스템은 아직 키가 없어 미분양을 모으지 않습니다.

  • HUG 다운로드 버튼은 정적 링크가 아닙니다. JS가 ① 이번 달 파일 ID 조회 ② 캡차 필요 여부 확인 ③ 다운로드의 3단계를 밟습니다. 이 흐름을 그대로 재현해 2026-09-13에 CSV 11,050행을 받았습니다.
  • 조인: 공고와 주택형은 HOUSE_MANAGE_NO로 붙습니다. 공고 자체의 키는 PBLANC_NO입니다.

공공 API에서 실제로 밟은 함정

공공 API는 문서와 실제 응답이 자주 다릅니다. 아래는 실제로 겪었거나 실데이터에서 발견한 것들 가운데, 비개발자도 알아 두면 좋은 7개입니다. 나머지는 접어 두었습니다. 대부분 에러 없이 조용히 틀린 숫자를 만든다는 점이 무섭습니다.

공급면적과 전용면적

생긴 일 청약홈은 공급면적, 실거래가는 전용면적을 줍니다. 공급면적이 전용보다 1.43~1.49배 커서, 그대로 비교하면 분양가가 30~40% 싸 보이고 안전마진이 가짜로 부풉니다.

막은 법 전용면적을 주택형 이름(예: "055.9700A" → 55.97㎡)에서 따로 뽑습니다. 모양이 다르면 짐작하지 않고 비교에서 뺍니다.

같은 이름의 구

생긴 일 "중구"는 서울·부산·대구·인천에 다 있습니다. 이름만 보면 부산 공고가 서울로 붙습니다. "광주시"는 경기 광주시와 광주광역시가 같은 글자이고, "남양주시" 안에는 "양주시"가 들어 있습니다.

막은 법 시·도가 먼저 맞아야 인정합니다. 이름 일부만 겹치는 경우는 버립니다.

최근 두 달 착시

생긴 일 실거래는 계약 후 30일 안에 신고합니다. 2026-09-13 시점에 4월 거래는 15,037건인데 9월은 1,606건이었습니다. 거래가 준 게 아니라 신고가 덜 끝난 것입니다.

막은 법 비교 기간을 "이번 달의 두 달 전"에서 끝냅니다. 모자란 표본은 기간을 늘려 메웁니다.

빈 값을 0으로

생긴 일 빈칸이나 "-"를 0으로 바꾸면 "값 없음"과 "0"이 구분되지 않습니다. 경쟁률 0 같은 거짓 정보가 생깁니다.

막은 법 빈 값은 빈칸(값 없음)으로 둡니다. 모르는 값이 와도 그 칸만 비우고 전체 수집은 계속합니다.

0건을 성공으로

생긴 일 인증키 미적용, 주소 변경, 사용량 초과가 모두 에러 없이 "0건"으로 나타납니다. 에러 화면을 정상 응답처럼 주기도 합니다.

막은 법 0건은 "비었음"으로 분류해 실패와 같게 취급합니다. 단 거래 없는 달은 정상이라, 일부 지역 0건과 전체 0건을 구분합니다.

임대 공고 섞임

생긴 일 행복주택·국민임대 공고 149건이 보증금을 분양가 칸에 담은 채 섞여 있었습니다.

막은 법 분양/임대 구분을 저장하고, 임대는 판정과 안전마진에서 뺍니다.

해제 거래·토지임대부

생긴 일 계약이 해제된 거래(표본의 2.07%)와 땅값이 빠진 토지임대부 거래가 시세 비교에 섞였습니다.

막은 법 두 정보를 저장하고 비교에서 뺍니다.

경쟁률 칸의 정체라이브 첫 페이지에서 '(△6)' 때문에 죽었다. 실측 모양은 숫자 21.66%, 미달 "(△N)" 30.57%, "-" 47.75%, null 0.02%. 문서엔 없다.원문은 항상 보존. 숫자는 경쟁률 칸, 미달 N은 미달 세대수 칸에 따로 넣는다. 전부 못 읽으면 "의심" 상태로 표시한다.

안전마진 계산

"분양가가 주변 시세보다 얼마나 싼가"를 한 숫자로 냅니다. 주변 시세는 평균이 아니라 싼 쪽 4분의 1 지점(P25)을 씁니다. 일부러 낮게 잡은 기준선이라 숫자가 보수적으로 나옵니다.

안전마진 = 1 − (분양가 ÷ 전용면적) ÷ P25(주변 실거래 금액 ÷ 전용면적)

+면 분양가가 주변 싼 거래들보다도 싸다는 뜻이고, −면 그만큼 비싸다는 뜻입니다. −40%면 분양가가 그 P25 가격의 1.4배입니다.

2026-09-13 당시 공개 페이지 기준으로, 마진이 계산된 93개 주택형 중 85개가 −였고 중앙값은 −31%였습니다. 이유는 세 가지입니다. P25가 일부러 낮게 잡은 기준선이고, 열린 공고가 주로 수도권 외곽·지방 택지였으며, 구 단위로 묶어 비교하는 데 한계가 있습니다(위 분당 예처럼). −는 "비싸다"는 판정이 아니라 "이 구의 싼 거래들과 거리가 멀다"로 읽어야 합니다.

개발자용 — P25와 실패 처리 
import math
def p25(values):                       # 보간 없는 nearest-rank
    v = sorted(values)
    return v[math.ceil(len(v) * 0.25) - 1]
  • 선형보간 P25는 표본 4~15건 수준에서 존재하지 않는 값을 만들고, 그 값이 항상 더 높아 마진이 낙관적으로 나옵니다. 테스트로 고정했습니다(보간이면 0.5111, nearest-rank면 0.5).
  • 보수성은 P25 하나로만 넣습니다. 1.05/0.95 같은 임의 보정 계수를 쓰지 못하게 하는 테스트가 있습니다.
  • 금액이 NULL인 행은 정렬에서 TypeError를, 전부 0원인 표본은 0으로 나누기 에러를 냈습니다. SQL에서 NULL·0 이하를 걸러내고 파이썬에서 한 번 더 거릅니다. 통과한 값만 표본 수에 셉니다.
  • 마진 값 자체가 없으면 "표본부족"으로 표시하지 않고 에러로 실패합니다. "표본부족"은 "봤는데 모자랐다"이지 "아무도 안 봤다"가 아니기 때문입니다.
  • 분양가는 주택형별 최고액을 씁니다. 그래서 마진이 더 적게, 보수적으로 나옵니다.

  • 겹쳐 돌지 않기. 이미 돌고 있으면 기다리지 않고 이번 회차를 건너뜁니다.

version = conn.execute("PRAGMA user_version").fetchone()[0]
if version > SCHEMA_VERSION:

for target, sql in MIGRATIONS:          # [(2, DDL), (3, DDL), ... (8, DDL)]

        conn.execute(f"PRAGMA user_version = {target}")
        version = target
conn.commit()

숫자 정규화 (문자열·숫자 모두 받고, 빈값은 NULL, 쉼표 제거, 예외 없음)

def to_float(value):
    if value is None:
        return None
    if isinstance(value, str):
        value = value.strip()
        if value in ("", "-"):
            return None
        value = value.replace(",", "")   # "7,474.67"
    try:
        return float(value)
    except (ValueError, TypeError):
        return None

import re
_SHORTFALL_RE = re.compile(r"^\(△(\d+)\)$")
def parse_rate(raw):                  # -> (ratio, shortfall, unparsed)
    ratio = to_float(raw)
    if ratio is not None: return ratio, None, False
    text = raw.strip() if isinstance(raw, str) else raw
    if text in (None, "", "-"): return None, None, False
    m = _SHORTFALL_RE.match(text) if isinstance(text, str) else None
    return (None, int(m.group(1)), False) if m else (None, None, True)
